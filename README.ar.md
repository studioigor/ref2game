## التثبيت بأمر واحد

أرسل هذا التوجيه (prompt) إلى وكيلك (Claude Code أو Codex):

```text
Install the skill ref2game https://github.com/studioigor/ref2game
```

يحتوي المستودع على نسختين من المهارة نفسها. يستخدم Claude Code مجلد `claude/`، بينما يستخدم Codex مجلد `codex/`. بعد ذلك، أرسل الأمر `/ref2game` في Claude Code أو الأمر `$ref2game` في Codex مع إرفاق الصورة المرجعية الخاصة بك.

---

يقوم **ref2game** بتحويل الصورة المرجعية إلى نموذج أولي متكامل للعبة يمكنك تجربته ولعبه في المتصفح. يتم توليد العناصر الرسومية قطعة تلو الأخرى، وبنفس أسلوب الصورة المرجعية. كل ما يتحرك يُدار برمجياً عبر محرك مصغر مبني على WebGL2: الهياكل الحركية (rigs)، ودورات المشي، والرياح، والإضاءة، والجسيمات، والكاميرا، وواجهة المستخدم (HUD)، والشعور باللعبة (game feel). تشاهد الصفحة تتغير وتتطور أمام عينيك أثناء عمل الوكيل.

**الذكاء الاصطناعي يرسم. والشيفرة البرمجية تبث الحياة.**

## نسختان للمهارة

| | `claude/` مخصصة لـ Claude Code | `codex/` مخصصة لـ Codex |
|---|---|---|
| توليد الصور | حسب اختيارك: أداة image_gen المدمجة في Codex، أو أي واجهة برمجية للصور API (يبحث عنها الوكيل ويربطها فوراً، وفق ميزانية تحددها أنت)، أو أداة محلية، أو إفلات الصور يدوياً | أداة توليد الصور المدمجة في الجلسة |
| الأسئلة | خيارات متعددة مع اقتراح الإجابة الموصى بها | عبر أداة الإدخال الخاصة بـ Codex، أو بإيجاز عبر المحادثة |
| النُقّاد (Critics) | وكلاء فرعيون في الخلفية؛ وتصل التقييمات في الرسالة التالية | وكلاء فرعيون؛ وتُدمج النتائج قبل انتهاء الجولة الحالية |

المحرك، والهياكل الحركية، والفحوصات، والمراجع متطابقة في كلتا النسختين.

## كيف تبدو التجربة في الواقع

```text
أنت      /ref2game  [لقطة شاشة للعبة إطلاق نار على الزومبي بمنظور من أعلى]
الوكيل   جولة أسئلة واحدة: ما هو مولد الصور، ماذا يفعل اللاعب، وما هو حجم النموذج المطلوب.
الوكيل   الصفحة المباشرة جاهزة: المستوى يعمل حالياً بعناصر نائبة (placeholders).
الوكيل   العناصر الفنية تصل قطعة تلو الأخرى: الخلفية، الأرضية، المجسمات، البطل، الحشود.
الوكيل   البوابة A: المرجع بجانب إطارنا الحالي، مع قياس الفروقات رقمياً.
الوكيل   الهياكل الحركية، الرياح، الإضاءة، المؤثرات الحماسية. "جرّب WASD + الفأرة، والاندفاع بـ Space، وفجّر خزان الوقود."
أنت      الزومبي ينزلقون وأقدامهم تتزحلق على الأرض.
الوكيل   تم تثبيت مسارات الأقدام، وحركة الركبتين عبر IK. فحص انزلاق القدم يعمل الآن مع كل تعديل.
```

## مراحل العمل (The Pipeline)

| # | المرحلة | دورك | دور الوكيل |
|---|---|---|---|
| 0 | المعاينة والاستفسار | الإجابة على جولة واحدة من الأسئلة | دراسة المرجع، وسؤال ما لا يمكن حسمه من الصورة وحدها |
| 1 | الإعداد والدراسة | فتح الرابط المباشر | تجهيز هيكل المشروع، ودليل الأسلوب الفني، وتخطيط المرجع، والخطة؛ وتعمل الصفحة بعناصر نائبة (placeholders) |
| 2 | أول إطار حقيقي | معاينة الإطار بجانب المرجع | توليد متوازٍ، والتقطيع، والشفافية (alpha)، واعتماد مظهر البطل، والمؤثرات؛ فحوصات ونُقّاد آليون |
| 3 | بث الحياة | اللعب والتجربة | هياكل حركية لكل شخصية، ورياح، وعالم متفاعل، وكاميرا، ومؤثرات حركية، وعرض تجريبي تلقائي (attract demo) |
| 4 | الملاحظات | توضيح ما يحتاج لإصلاح | الإصلاح في الشيفرة أو إعادة التوليد، ثم إضافة فحص آلي يمنع تكرار المشكلة مستقبلاً |
| 5 | التسليم | استلام ملف zip | بناء ساكن قابل للتشغيل، والنسج الرسومية (textures)، وملف البيان (manifest)، والشيفرة المصدرية |

## ما الذي يجعله مختلفاً

- 🎨 **الذكاء الاصطناعي يرسم، والبرمجة تتحكم.** قطعة واحدة لكل عملية توليد، مع الالتزام الدائم بالمرجع ودليل الأسلوب الفني. التوهج، والظلال، والجسيمات، والنصوص، والمياه لا تُدمج نهائياً داخل الصورة الثابتة: بل يتحكم بها المحرك بالكامل، فلا يتجمد أي عنصر ولا تتضاعف التأثيرات بشكل مشوه.
- 🦴 **هياكل حركية حقيقية، وليست مجرد صور تهتز (sprites).** كل شخصية أو عنصر، بدءاً من اللاعب وحتى الحصان بجوار الموقد، يحصل على هيكل مقطوع الأجزاء (cut-out rig): أطراف ثنائية العظام، ومفاصل دائرية، وأوجه قريبة وبعيدة. تنثني الحيوانات المرسومة عبر عظام ناعمة داخل مظلل الرسوم (shader). تحريك الصورة بالكامل كوحدة واحدة لا يُعد تحريكاً حقيقياً أبداً.
- 📏 **الحركة تخضع للقياس الدقيق.** يبلّغ كل هيكل حركي عن إحداثيات مفاصله. ويقوم سكريبت ضمان الجودة (QA) بفحص انزلاق القدم، والعرج، وطول الخطوة، وانثناء الركبة، والتمدد، ومرحلة حركة الذراعين، والانتقالات المفاجئة بين الحالات، وما إذا كان السيف يصيب الهدف بدقة في إطار الاصطدام للأهداف من كافة الاتجاهات.
- 🌬️ **الحيوية تعني أنظمة متكاملة.** حقل رياح واحد ذو هبات متنقلة يحرّك العشب والأشجار والأردية والفوانيس. يتفاعل العالم بحيوية مع اللاعب، ويحصل كل حدث على طبقات من المؤثرات المعززة للشعور (juice).
- 🔍 **نُقّاد مستقلون.** نُقّاد للأصول، والوحدات، والحركة، والإطارات، ومدى المطابقة، وأسلوب اللعب يعملون في الخلفية. ويقوم ناقد المطابقة بمقارنة إطارك بالصورة المرجعية بلغة الأرقام: التكوين، وتدرجات الإضاءة، ولوحة الألوان، وبقع الضوء، وأحجام الشخصيات.
- ⚡ **تقدم ملموس خلال دقائق.** تُعيد الصفحة تحميل نفسها تلقائياً في غضون ثانية واحدة بعد كل تعديل، مع الاحتفاظ بحالة اللعب. وتتم عمليات توليد الرسوم بالتوازي أثناء كتابة المؤثرات.
- 🧷 **كل عيب يتحول إلى اختبار تحقق.** أي مشكلة تبلّغ عنها يتم إصلاحها، ثم يُضاف فحص آلي جديد يضمن عدم تكرار هذا النوع من العيوب مجدداً.
- 🕹️ **أي نوع من ألعاب ثنائية الأبعاد، وبأي أسلوب فني.** ألعاب منصات (platformer)، أو منظور من أعلى (top-down)، أو أيزومتري (isometric)، أو إطلاق نار (shmup)، أو ألغاز، أو ألعاب بطاقات؛ وبأسلوب البكسل، أو الرسم، أو الكرتوني والحبر (cel & ink)، أو الفيكتور المسطح، أو الألوان المائية، أو النيون.

## عبارات مقترحة للتجربة

- *"Make a game like this"* (اصنع لعبة تشبه هذه) مع إرفاق لقطة شاشة
- *"Bring this concept art to life as a platformer"* (ابث الحياة في هذا الفن المفاهيمي وحوّله إلى لعبة منصات)
- *"Make a playable slice in the style of this video"* (أنشئ جزءاً قابلاً للعب بأسلوب هذا الفيديو)
- *"The legs slide when he walks"* (أقدامه تنزلق أثناء المشي) — أثناء تشغيل المشروع والعمل عليه
- *"Pack it up"* (احزم المشروع) — للحصول على بناء ساكن قابل للتشغيل وحزمة الأصول

## المتطلبات

Claude Code أو Codex، و Python 3.9+ مع مكتبات Pillow و NumPy و SciPy، و Node.js 18+، ونظام تشغيل macOS أو Linux.
يتم تثبيت Playwright مع متصفح Chromium تلقائياً داخل المهارة عند التشغيل لأول مرة. يلزم وجود ffmpeg فقط عند استخدام مراجع الفيديو أو تصدير عروض الفيديو.
